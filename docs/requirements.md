## 1. 背景と目的

### 1.1 課題

口座残高を見ても「本当に自由に使えるお金」が分からない。**支払うと確定している支出が残高に残っている**ためである。ライブや旅行に行くと決めた時点でそのお金は自分のものではないが、まだ引き落とされていないため残高には含まれている。実際より裕福に見える。

また、欲しいものや将来の大きな買い物に対して「あといくら足りないのか」が把握できておらず、判断ができない。

**貸借について。** 当初は「他人のために立て替えた金額が残高から抜けているため実際より貧乏に見える」ことを2つ目の課題としていた。**これは実際に使ってみて成立しないことが分かった。** 現金で立て替えた場合はその通りだが、カードで立て替えた場合は現金がまだ出ていないため、残高から抜けていない。「立て替えた ＝ 現金が出た」と決め打ちできない。

そのため貸し借りは実質資産の計算から外し、**「相手から返ってくる予定の額」として別枠に表示する**ことにした。把握したいという要求そのものは残っているが、残高と足し引きする形では正しく表せない。

### 1.2 目的

- 確定支出を加味した **実質的な資産額** を一目で把握できるようにする
- 貸している額と借りている額の未精算分を、**実質資産とは別の参考値** として把握できるようにする
- 欲しいもの・やりたいこと・将来の目標を一元管理し、**目標までの不足額** を把握できるようにする

### 1.3 副次的な目的（開発上）

- ドメインモデリング、レイヤードアーキテクチャ、テスト設計の実践の場とする
- 生成コードやライブラリ実装のコードリードを通じて理解を深める

上記のため、機能の豊富さより **設計の筋の良さ** を優先する。

## 2. スコープ

### 2.1 対象

- 保有資産（現金・預金）の管理
- 貸借（貸した分・借りた分の両方）の管理と精算の記録
- 支払い確定済みの予定支出の管理
- 欲しいもの・やりたいこと・目標の管理と不足額の算出
- 上記を統合したダッシュボード表示

### 2.2 対象外（今回は作らない）

| 項目 | 理由 |
| --- | --- |
| 銀行API連携による残高自動取得 | 個人開発では契約面で現実的でない |
| レシート読み取り・OCR | 目的に対して不要 |
| 日々の生活費の記録（食費、光熱費等の家計簿） | 既存アプリの領域。目的外 |
| 複数ユーザー・共有機能 | 個人利用のため |
| 外貨・為替 | 日本円のみ扱う |
| 予算管理・支出分析レポート | 目的外 |
| 確定支出の分割払い | 内金・残金のような分割は扱わない。金額は一括で扱う |
| 投資資産の実質資産への算入 | 別枠の参考値として表示するのみ（`docs/domain.md` 3章参照） |
| 貸借の実質資産への算入 | 別枠の参考値として表示するのみ（1.1 で変更。3章参照） |

### 2.3 前提

- 残高の更新は **手動入力** とする。入力頻度は月1回程度で成立する設計にする
- 扱う通貨は日本円のみ。金額は円単位の整数で扱う

## 4. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 利用者 | 単一ユーザー。ただし複数端末（スマホ・タブレット・PC）のブラウザから利用する |
| 認証 | 単一ユーザー向けの簡易な認証を設ける。資産額を扱うため無認証は避ける |
| データ保管 | サーバー側のDBに保管し、端末間で同期する |
| オフライン対応 | 初期スコープ外。通信前提とする |
| 性能 | データ件数は年間数百件規模を想定。特別な最適化は不要 |
| 可用性 | 個人利用のため停止許容。SLA は定めない |
| テスト | 実質資産・不足額の計算ロジックは外部依存を持たない純粋関数とし、ユニットテストを必須とする。あわせて、**型チェック・lint・ユニットテスト・E2E が単一コマンドで完走すること**を front の要件とする |
| セキュリティ | 通信はHTTPS。認証情報はブラウザの `localStorage` に保管する。単一ユーザー・自分の端末のみという前提のもとで許容する |
| **コスト** | **月額0円で運用する。** 無料枠を超える構成は採用しない（5章。担保の仕組みは `docs/architecture.md` 1章） |
| インフラ管理 | 構成はリポジトリ内のファイル（`wrangler.jsonc` / `migrations/`）で管理し、コンソールでの手動設定に依存しない |

## 5. 技術構成

**構成の詳細と、そうした理由は `docs/architecture.md` にある。** ここには要件として外せない点だけを挙げる。

| 要件 | 内容 |
| --- | --- |
| **月額0円** | クレジットカードを登録せず、無料枠を超える構成を採らない。**どう担保しているかは `docs/architecture.md` 1章** |
| コールドスタート無し | 月1回程度の利用でも待たされない |
| 単一コマンドで検証が完走する | 型チェック・lint・ユニットテスト・E2E が `npm run check` で通ること。エージェントのループの停止条件になる |
| 構成をリポジトリで管理する | `wrangler.jsonc` / `migrations/` で管理し、コンソールでの手動設定に依存しない |

これらを満たす構成として **Cloudflare Workers + D1 + TypeScript** を採っている。当初は Go + PostgreSQL + Cloud Run だったが、「クレジットカードを登録しない」制約が加わった時点で GCP が落ちた（無料枠を使うだけでも請求先アカウントが必須のため）。経緯は `docs/decisions.md`。
